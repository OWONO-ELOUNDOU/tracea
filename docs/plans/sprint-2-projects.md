## 1. Objectif

Un utilisateur connecté retrouve ses projets sur l'écran « Mes projets », en crée un (nommé, vide, rattaché à son compte), le renomme, le duplique et le supprime. Aucun utilisateur ne peut lire ni modifier le projet d'un autre : toute tentative reçoit 404. Le parcours connexion → Mes projets → créer un projet est vérifié dans un navigateur, avec contrôle d'accessibilité automatique. Les sessions expirées et les projets en corbeille depuis plus de 30 jours sont purgés.

La table `versions` est créée dès ce sprint parce que `projects.current_version_id` et la duplication en dépendent ; elle reste vide tant que la génération n'existe pas (sprint ultérieur). `versions.model` contiendra un `BuildingModel` tel que défini par `packages/domain` : rien dans ce sprint ne crée de représentation parallèle du bâtiment, et la vignette d'un projet (`thumbnailUrl`) sera plus tard dérivée du modèle, jamais d'un export.

## 3. Contrat des routes `/projects`

Ce contrat est la référence commune du backend (S2-3) et du frontend (S2-5). Tout écart découvert en cours de sprint est signalé et reporté ici avant d'être codé.

### 3.1 Conventions communes

- Chemins sans préfixe de version, comme `/auth/*` et `/me` aujourd'hui (voir décision ouverte D5).
- Toutes les routes exigent une session valide : sinon 401 `UNAUTHENTICATED`.
- `POST`, `PATCH`, `DELETE` exigent l'en-tête `X-CSRF-Token` égal au cookie `tracea_csrf` : sinon 403 `CSRF_TOKEN_INVALID` (comportement existant du plugin de session).
- Erreurs au format Problem Details (`application/problem+json`) avec `code`, `title` et `detail` en français.
- Isolation : un projet inexistant, supprimé, appartenant à un autre utilisateur, ou un `{id}` qui n'est pas un UUID bien formé reçoivent tous la **même** réponse 404 `PROJECT_NOT_FOUND` (titre « Projet introuvable », corps identique à l'octet près hors identifiant de requête). Jamais 403.
- Corps de requête validés par un schéma Zod strict : toute clé inconnue (`ownerId`, `id`, `deletedAt`, …) est refusée par 422 `VALIDATION_ERROR` avec `fields`.
- Dates ISO 8601 UTC ; identifiants : chaînes UUID opaques pour le client.
- Limitation de débit : limite globale existante (`RATE_LIMIT_PER_MINUTE`), réponse 429 `RATE_LIMITED`.

### 3.2 Types de réponse

```ts
interface ProjectSummary {
  id: string;
  name: string;
  createdAt: string;
  updatedAt: string;
  thumbnailUrl: string | null; // toujours null au sprint 2
  currentVersion: { number: number } | null; // toujours null au sprint 2
}

interface ProjectDetail {
  id: string;
  name: string;
  descriptionText: string | null;
  parameters: Record<string, unknown> | null; // toujours null au sprint 2
  site: Record<string, unknown> | null; // toujours null au sprint 2
  createdAt: string;
  updatedAt: string;
  thumbnailUrl: string | null;
  currentVersion: {
    id: string;
    number: number;
    origin: "generated" | "edited" | "restored";
    createdAt: string;
  } | null;
  lastJob: null; // réservé : la table jobs n'existe pas encore
}
```

`ownerId` et `deletedAt` ne sont jamais exposés.

### 3.3 Routes

| Méthode | Route                      | Requête                                               | Succès                                               | Erreurs propres à la route                      |
| ------- | -------------------------- | ----------------------------------------------------- | ---------------------------------------------------- | ----------------------------------------------- |
| GET     | `/projects`                | Paramètres `limit` (1 à 50, défaut 20) et `cursor`    | 200 `{ items: ProjectSummary[], nextCursor }`        | 422 `VALIDATION_ERROR` (`limit`, `cursor`)      |
| POST    | `/projects`                | Corps `{ name }`                                      | 201 `{ project: ProjectDetail }`, en-tête `Location` | 422 `VALIDATION_ERROR` (`name`)                 |
| GET     | `/projects/{id}`           | —                                                     | 200 `{ project: ProjectDetail }`                     | 404 `PROJECT_NOT_FOUND`                         |
| PATCH   | `/projects/{id}`           | Corps `{ name?, descriptionText? }`, au moins une clé | 200 `{ project: ProjectDetail }`                     | 404 `PROJECT_NOT_FOUND`, 422 `VALIDATION_ERROR` |
| POST    | `/projects/{id}/duplicate` | Corps vide                                            | 201 `{ project: ProjectDetail }`, en-tête `Location` | 404 `PROJECT_NOT_FOUND`                         |
| DELETE  | `/projects/{id}`           | —                                                     | 204 sans corps                                       | 404 `PROJECT_NOT_FOUND`                         |

Erreurs communes à toutes les lignes : 401, 403 (mutations), 429.

### 3.4 Règles de détail

- **Liste** : uniquement les projets de l'utilisateur dont `deleted_at` est nul, triés par `updatedAt` décroissant puis `id` décroissant. `nextCursor` vaut `null` sur la dernière page ; sinon c'est une chaîne opaque à renvoyer telle quelle dans `cursor`. Un curseur illisible donne 422 avec `fields.cursor`. La pagination ne saute ni ne répète aucun projet lorsque plusieurs projets ont le même `updatedAt`.
- **`name`** : chaîne, espaces de début et de fin retirés, 1 à 120 caractères après nettoyage, sans caractère de contrôle. Deux projets du même utilisateur peuvent porter le même nom (voir D9).
- **`descriptionText`** : chaîne de 0 à 2 000 caractères ou `null` (borne fixée par le rôle sécurité). Aucun écran ne l'édite à ce sprint ; la route l'accepte pour préparer CU-03.
- **`parameters` et `site`** : colonnes créées, toujours `null`, **refusées en écriture** (422, clé inconnue) tant que leurs schémas Zod n'existent pas dans `packages/domain` (voir D6).
- **Création** : projet vide (`descriptionText`, `parameters`, `site`, `currentVersion` nuls), `owner_id` pris dans la session, jamais dans le corps.
- **Modification** : met à jour `updated_at`. Un corps sans aucune clé reconnue donne 422.
- **Duplication** : nouveau projet du même propriétaire, nom `"<nom> (copie)"` (le nom d'origine est tronqué pour que le total reste ≤ 120 caractères), mêmes `descriptionText`, `parameters`, `site`. Si le projet source a une version courante, elle est copiée comme version numéro 1 du nouveau projet (même `model`, `model_schema_version`, `origin`, `seed`, `warnings`) et devient sa version courante ; les autres versions ne sont pas copiées. Projet et version sont créés dans une seule transaction.
- **Suppression** : logique (`deleted_at = now()`), corbeille de 30 jours. Un projet supprimé disparaît de la liste et répond 404 sur toutes les routes, y compris un second `DELETE`. La purge définitive est faite par S2-4. Aucune route de restauration à ce sprint (voir D3).
- **Journal d'audit** : `project.create`, `project.update`, `project.duplicate`, `project.delete` avec `target_type = "project"` et `target_id` ; ni nom ni description dans `metadata`.

## 8. Risques

| Risque                                                                                                                                                                  | Effet                                                                   | Parade prévue                                                                                                                                      |
